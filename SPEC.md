# Specification — Transfer Learning for Next-Day PM2.5 at Newly Deployed Stations

Written to be usable as the paper's Methods section with light editing, and precise
enough to reimplement the pipeline from this text alone. Every number here was produced
by the code in `aq/` and is regenerated by `python run.py --stage all`.

**Scope note.** Numbers in this document are computed under the corrected gap-interpolation
rule (§1.3). `FINDINGS.md` records the pre-correction values; §7.4 tabulates the deltas.

---

## 1. Data

### 1.1 Source and resolution

Ground-based PM2.5 measurements from the Abu Dhabi environmental monitoring network,
supplied as a single Excel workbook with **one worksheet per station**. Each row carries
`ts, Station_name, city, Longitude, Latitude, PM2.5`.

**Temporal resolution is DAILY.** Each row is one station-day. Earlier drafts of this
work described the data as hourly in three places; that is wrong. It follows that
**no hour-of-day feature exists or can exist** — any draft describing one is describing
a feature that was never computed.

| Property | Value |
|---|---|
| Stations | 27 |
| Rows in the workbook | 28,806 |
| **Non-null PM2.5 records (raw)** | **25,577** |
| Records after daily reindex + gap interpolation | 25,885 |
| Days on the union daily grid | 32,838 |
| Observed range | 0.62 – 491.75 µg/m³ |
| Median / mean | 34.47 / 39.45 µg/m³ |
| Station-days ≥ 75 µg/m³ | 6.34% |
| First workbook row / first non-null PM2.5 / last | 2017-02-10 / 2017-02-17 / 2024-11-07 |
| Lag-1 autocorrelation | ≈ 0.67 – 0.74 |

**The sample size to cite is 25,577**, the raw non-null count. Earlier drafts cited
28,806, which is the workbook row count including rows whose PM2.5 is missing. The
25,885 figure is a *derived* quantity (post-interpolation) and should not be presented
as the number of measurements.

> **Date span — state which date you mean.** The first workbook row is dated
> **2017-02-10**, but the first row carrying a non-null PM2.5 value is **2017-02-17**
> (a week later). Earlier drafts and `FINDINGS.md` gave "2017-01-01", which is wrong on
> both counts. The paper should say "PM2.5 observations span 2017-02-17 to 2024-11-07".

### 1.2 Cleaning rules

Applied per station, in order:

1. Drop rows with no timestamp.
2. Coerce PM2.5 to numeric; non-numeric becomes missing.
3. **Clip at `PM_CAP = 500.0` µg/m³.** The observed maximum (491.75) falls below the cap,
   so no value is actually clipped; the rule guards against sensor spikes.
4. Reindex onto a **complete daily grid** from the station's first to its last observation.
   Days outside that span are not created — a station contributes nothing before it was
   deployed or after it was retired.
5. Interpolate short gaps (§1.3).

Timestamps are normalised to midnight; a trailing `Z` is stripped before parsing.

### 1.3 Gap interpolation — the rule is per-RUN, not per-value

**Linearly interpolate an interior run of missing days if and only if the run is at most
`MAX_GAP = 3` days long. A longer run is left entirely missing. A run touching either end
of a station's record is never interpolated, because nothing brackets it.**

The emphasis is necessary. `pandas.Series.interpolate(limit=3)` does *not* implement this
rule: `limit` caps the number of *consecutive fills within* a run, so a 7-day gap has its
first three days synthesised and the remaining four left missing. All seven original
scripts used that call. Corpus-wide it fabricated **306 values across 102 over-long runs**.

| Run length | `interpolate(limit=3)` | This specification |
|---|---|---|
| 1–3 days (interior) | filled | filled |
| 4 days (interior) | **first 3 filled** | **none filled** |
| 7 days (interior) | **first 3 filled** | **none filled** |
| any run touching an endpoint | none filled | none filled |

Implemented in `aq.data._interpolate_short_gaps`; enforced by six tests in
`tests/test_invariants.py`. Correcting it moved the record count from 26,191 to 25,885.

Median distance from a target to its nearest source station is **5.3 km** (range 0.2 –
26.8 km). This tight clustering is the mechanistic explanation for why source selection
does not matter (§7.3): with sources this close, the pooled model already contains
whatever a nearby single source would contribute.

## 3. Protocol

For each target station *j*, with adaptation window length *K*:

### 3.1 Sources

All rich stations, restricted to `date ≤ (first observation of j) − 1 day`.

The cutoff is **strict**: source training data must end the day *before* the target was
deployed. Asserted in `aq.splits.source_frames`, which raises `LeakageError` otherwise.
Scalers are fit on this source data only and are never refit on adaptation or test data.

### 3.2 Adaptation

The target's first *K* days, `[first, first + K)`. Used for fine-tuning, for calibration,
and for any similarity metric. Never used to fit a scaler and never scored.

### 3.3 Test

Strictly after the adaptation window: `date ≥ first + K`. A target is retained only if at
least **`MIN_TEST = 60`** usable days remain, where "usable" means the day has a complete
lag window and an observed target value.

Splits are always by **absolute date**, never by random partition.

### 3.4 The 14-day lag window and its consequences

With `SEQ_L = 14`, a prediction for day *t* consumes days *t−14 … t−1*. Therefore:

- **The first predictable day of a station's life is day 15.**
- **K < 14 yields ZERO usable adaptation sequences.** K = 14 also yields zero, since day 15
  is the first predictable day and the window `[first, first+14)` ends at day 14.
- K = 30 yields roughly 16 adaptation sequences; K = 90 yields roughly 76.
- **A true zero-shot cold start is impossible in this model class.** Reporting a "cold-start
  advantage curve" over K ∈ {0, 7, 14} is meaningless — those three settings are
  structurally identical.
- Any path that fits parameters on the adaptation window (fine-tuning, calibration)
  therefore **requires K ≥ 30**, enforced by `aq.splits.require_adaptation_k`.

### 3.5 Simulated transfer (secondary)

A target is held out entirely from the source pool and the cut is placed at 2023-01-01.
Reported as a secondary analysis; the authentic protocol above is primary.

## 4. Features

### 4.1 Temporal design (always present) — 18 columns

| Columns | Content |
|---|---|
| 0 – 13 | target PM2.5 at *t−14 … t−1*, **oldest first** |
| 14 – 17 | sin/cos of day-of-week (period 7), sin/cos of day-of-year (period 366) |

Column 13 is the *t−1* value. It doubles as the **persistence baseline**, and is read
directly off the design matrix (`Design.persistence`) rather than recomputed, which makes
it impossible for the baseline and the model to be scored on different rows.

A row is retained only if all 14 lags and the target value are observed.

### 4.2 Spatial neighbour features (optional) — 2k further columns

Given the *k* nearest source stations, ordered nearest-first by great-circle distance:

| Columns | Content |
|---|---|
| 18 … 18+k−1 | each neighbour's value at *t−1* |
| 18+k … 18+2k−1 | each neighbour's (*t−1*) − (*t−2*) difference |

The level captures the regional background; the difference captures an advancing front,
since dust events arrive upwind-first. Both are strictly past-only with respect to *t*.

Optionally each neighbour block may be weighted by `exp(−distance / τ)`. Note this is
**mathematically a no-op at k = 1**, where a single weight normalises away — identical
RMSE across τ values at k = 1 is arithmetic, not evidence.

### 4.3 When a neighbour reading is unavailable

**If any neighbour's *t−1* value is missing, the row is dropped.** A missing *t−2* only
zeroes that neighbour's difference term; it does not drop the row, because the level is
the informative part.

**This asymmetry is why `build_common_index()` is mandatory rather than a convenience.**
Requesting neighbours strictly reduces the set of predictable days: for these targets the
temporal design covers ~331 test days while the k=8 spatial design covers ~134. The
reduction is not a defect to be engineered away — a spatial model genuinely cannot predict
a day whose spatial inputs do not exist.

What makes it dangerous is that **the surviving subset is easier**: persistence scores
12.97 on the complete-coverage days versus 19.14 on the full test set. Comparing a spatial
model on its 134 days against a temporal model on its 331 days therefore measures the
difference between two day-subsets, not the effect of the treatment. That is exactly how
this project produced, and then had to withdraw, a +35.6% extreme-event result (§7.1).

Note that both designs already came from **one shared function with a `spatial` flag**, and
that did not prevent the error — the divergence lives *inside* the flag, and the two call
sites look identical. Sharing a builder is not the safeguard. The safeguard is that the
evaluation index is computed once, across all arms, before any model is fit.

### 4.4 Sequence design (recurrent backbone)

Shape (n, 14, 5). Per timestep the channels are
`[pm25, dow_sin, dow_cos, doy_sin, doy_cos]`. The row-validity rule is identical to §4.1,
so a day usable by the ridge model is usable by the LSTM and vice versa.

## 5. Models

### 5.1 Persistence baseline

ŷ(t) = observed value at *t−1*, read from design column 13.

### 5.2 Ridge (primary)

`StandardScaler` → `Ridge(alpha=1.0)`, trained on the pooled source design. The scaler is
fit on source data only and reused unchanged at prediction time.

`random_state` is not set because it has no effect for the default (Cholesky) solver;
the fit is fully deterministic.

### 5.3 LSTM + attention

| Component | Setting |
|---|---|
| Architecture | LSTM(hidden=64, 1 layer, batch-first) → additive attention (32) → dropout(0.2) → Linear(1) |
| Attention | `u = tanh(W·h)`, `α = softmax(U·u)`, context `= Σ α·h` |
| Input | (n, 14, 5), feature-standardised using source statistics |
| Optimiser | Adam, lr = 1e-3 |
| Batch size | 128 |
| Loss | MSE |
| Max epochs | 40 |
| Validation split | final 10% of the source sequences, chronological |
| **Stopping rule** | early stopping on validation MSE, patience 6, `min_delta` 1e-4; the best state is restored |
| Source subsample cap | 20,000 sequences (keeps a full run feasible on one CPU) |
| Seed | 42, set immediately before each fit |

**Target standardisation is internal and not optional.** The model stores (µ, σ) of the
training targets, trains on `(y − µ)/σ`, and inverse-transforms at prediction. Training on
raw PM2.5 (mean ≈ 39) against standardised inputs forces the output layer to converge on a
large bias and, combined with early stopping, badly underfits — it cost roughly 4 µg/m³ of
RMSE (≈15.4 versus ≈11.5). The (µ, σ) pair is carried through fine-tuning, so a caller
cannot forget to apply it.

### 5.4 Fine-tuning

Two variants, both on the adaptation window, both requiring K ≥ 30:

| Variant | Trainable | Epochs | LR |
|---|---|---|---|
| Head-only | final linear layer | 20 | 1e-3 |
| Full | all parameters | 5 | 1e-4 |

Full-batch gradient steps (the adaptation window is ~16–76 sequences).

### 5.5 Linear calibration

Fit `ŷ_cal = α·ŷ + β` by least squares on the adaptation window only, then apply to test.

### 5.6 Similarity weighting

Geographic similarity `w_s = exp(−d(target, s) / τ)` with τ = 25 km, applied as
per-sequence sampling weights (`WeightedRandomSampler`) or as ridge `sample_weight`.
Weights are normalised to sum to the sample count.

### 5.7 Seasonal routing

UAE seasons: **cool = October–April**, **hot = May–September**.

Two backbones are trained, one per season. At prediction time **each day is routed to the
model matching that day's own season**. A seasonal model is trained only if its season has
more than `SEQ_L + 30` rows; if exactly one model exists, all days fall back to it, and
that fallback is explicit.

The original implementation ran both models over the whole test set and returned whichever
array was longer — it never routed at all (§7.3).

## 6. Evaluation

### 6.1 Metrics

RMSE (primary), MAE, median absolute error, R². All computed on the raw µg/m³ scale.

### 6.2 Slices

Let `y` be the observed test values and `θ` the station's 90th-percentile threshold.

| Slice | Definition |
|---|---|
| `all` | every test day |
| `normal` | `y < 75` |
| `ext` | `y ≥ 75` µg/m³ (absolute, "unhealthy") |
| `extrel` | `y ≥ θ` (relative, the station's top 10%) |
| `onset` | `y ≥ 75` today **and** `y < 75` yesterday |

`onset` isolates the days where persistence is structurally guaranteed to fail, so it is
the fairest test of whether a model adds anything on event days.

> **Terminology warning.** The word "extreme" denotes three different slices across the
> original scripts: the absolute ≥75 rule; the 90th percentile of a station's *full*
> series; and the 90th percentile of the *common test window*. `FINDINGS.md` §4.3 uses the
> first and §5.5 uses the third, so those two tables are not comparable. **The paper must
> not use one word for both.** This package keeps them distinct as `ext` and `extrel` and
> states which threshold basis is in use at each call site.

### 6.3 Minimum-sample rule and the resulting per-slice n

**A slice RMSE is reported only when the slice contains at least 5 qualifying days;
otherwise it is NaN.** Consequently the number of targets contributing differs by slice:

| Slice | Targets | Why |
|---|---|---|
| `all` | 12 / 12 | every target has ≥60 test days |
| `normal` | 12 / 12 | |
| `extrel` | 12 / 12 | a 10% threshold always yields enough days |
| `ext` (≥75) | **9 / 12** | 3 targets have fewer than 5 days ≥75 in their test window |
| `onset` | **7 / 12** | onset days are rarer still |

This is a **reporting rule, not an absence of events** — every target has at least 2
extreme days. Per-target extreme counts: 2, 4, 4, 6, 6, 9, 9, 11, 14, 18, 29, 32. Onset
counts: 1, 2, 3, 3, 3, 6, 6, 6, 7, 8, 19, 19. The paper must state the rule; reporting
"n = 9" without it invites the reading that three stations had no extreme pollution.

### 6.4 The common evaluation index — mandatory

Before any model is fit:

1. Build the design for **every arm** of the comparison, including the baseline.
2. Intersect their date indices.
3. Apply the test-window cut.
4. Require ≥ `MIN_TEST` surviving days, else skip the target.
5. Score **every** arm on exactly that index.

`aq.evaluate.score()` **raises `IndexMismatchError`** — it does not warn — if any method's
predictions differ from the index in length, content or order. A warning inside a long
stage log is a finding nobody reads.

Training pools may legitimately differ between arms; only the evaluation is held fixed.

### 6.5 Statistical tests

Two-sided **Wilcoxon signed-rank** over per-target RMSEs, paired by station.

**Report n, the win-rate, and a separate p-value for every slice.** A single p-value for a
multi-slice table is misleading here: after the gap fix, spatial features at k=1 are
p=0.0195 on the overall slice and p=0.4922 on the extreme slice. Quoting one number for
the row hides the disagreement.

With 12 targets the design is underpowered below roughly a 1% effect. State **"no evidence
of benefit"**, never "proof of no benefit".

**Multiplicity.** The neighbour ablation runs 10 tests (5 values of k × 2 slices). Raw
p-values in that grid must be Holm-corrected before any cell is called significant; see
§7.4 for a case where this matters.

## 7. Known failure modes

Four bugs have invalidated results in this project. Each is recorded with what it cost and
what now prevents it.

### 7.1 Test-set alignment — the most damaging

**Manifested** three times: (a) the Stage 4 spatial design was scored on ~140 days while
the temporal design was scored on ~331, and the smaller subset is easier; (b) an external
ablation scored persistence on 507 points against models on 508; (c) an early neighbour
ablation let the test set shrink as k grew.

**Cost:** the project's headline positive result. Spatial neighbour features were reported
to improve extreme-event RMSE by **+35.6%**. On a common index the effect is +2.3% and null.
The paper's contribution changed from positive to negative as a result.

**Now prevented by:** `evaluate.build_common_index()` as the sole mask producer and
`evaluate.score()` raising on mismatch. Tests: `test_score_raises_on_different_indices`,
`test_score_raises_on_different_lengths`, `test_common_index_is_the_intersection`,
`test_align_raises_when_design_cannot_cover_the_index`,
`test_common_index_holds_for_every_k`, `test_the_refuted_35_percent_claim_does_not_reappear`.

### 7.2 LSTM target scaling

**Manifested** as the LSTM appearing far weaker than ridge (RMSE ≈15.4 versus ≈11.5).
Training on raw targets with standardised inputs drove the output layer to a large bias;
early stopping then halted training while the model was still underfit.

**Cost:** would have supported a false conclusion that the neural model is not competitive
at all. After the fix it reaches ≈11.4–12.1 and **does** beat persistence significantly —
it is simply outperformed by ridge.

**Now prevented by:** standardisation internal to `LSTMBackbone`, (µ, σ) carried through
fine-tuning. Test: `test_lstm_predicts_in_raw_scale_and_does_not_collapse_to_the_mean`.

### 7.3 Seasonal routing

**Manifested** as `SeasonalBackboneWrapper.predict()` running both seasonal models on the
full test set and returning whichever array was longer. No prediction was ever routed by
season, so "seasonal specialisation" was inert while appearing to be enabled.

**Cost:** any claimed benefit from seasonal specialisation in earlier drafts is unsupported
— the mechanism was not running.

**Now prevented by:** `SeasonalRouter.predict` indexing by each day's own season, with an
explicit single-season fallback. Tests: `test_seasonal_router_routes_by_day_not_by_output_length`,
`test_seasonal_router_falls_back_when_one_season_is_missing`.

### 7.4 Gap interpolation

**Manifested** as `.interpolate(limit=MAX_GAP, limit_area="inside")` in all seven scripts.
`limit` caps consecutive fills *within* a run rather than skipping over-long runs, so the
first 3 days of every long gap were synthesised. **306 fabricated values across 102 runs.**
`stage1_foundation.py` shows the per-run rule was always the intent: its lines 72–78 build
a NaN-run classification and then never use it.

**Cost:** small but non-zero, and it inflated the reported sample size. Effect on the gate:

| Item | Before | After | Conclusion |
|---|---|---|---|
| ridge vs persistence, K=30 | +5.8%, 12/12, p=0.0005 | +5.8%, 12/12, p=0.0005 | unchanged |
| ridge vs persistence, K=90 | +6.2%, 12/12, p=0.0005 | +6.0%, 12/12, p=0.0005 | unchanged |
| ridge vs LSTM, K=30 | 10/12, p=0.0034 | 10/12, p=0.0068 | unchanged |
| ridge vs LSTM, K=90 | 10/12, p=0.0049 | 10/12, p=0.0034 | unchanged |
| LSTM vs persistence, K=30 | 11/12 | +3.1%, 12/12, p=0.0005 | stronger |
| LSTM vs persistence, K=90 | +1.7%, 10/12, p=0.027 | +4.1%, 12/12, p=0.0005 | stronger |
| normal days | +10.5%, p=0.0005 | +10.4%, p=0.0005 | unchanged |
| extreme ≥75 | −20.4%, 0/9, p=0.0039 | −20.6%, 0/9, p=0.0039 | unchanged |
| top-10% | −15.4%, 1/12, p=0.0010 | −15.6%, 1/12, p=0.0010 | unchanged |
| onset | −7.6%, 0/7, p=0.0156 | −7.8%, 0/7, p=0.0156 | unchanged |
| spatial k=1, overall | −1.4%, p=0.0098 | −0.8%, p=0.0195 | still adverse, weaker |
| spatial k=5, extreme | +1.3%, p=0.1602 | +2.8%, **raw p=0.0371** | see below |
| spatial k=8, extreme | +2.3%, p=0.4316 | +3.5%, p=0.3750 | unchanged (null) |

**No conclusion changes.** One cell needs stating plainly: after the fix, k=5 on the
extreme slice has a raw p below 0.05. It is treated as null for three reasons:

1. It does not survive Holm correction across the 10 tests in the grid (adjusted p = 0.334).
2. There is no dose-response. k=8 has a *larger* effect (+3.5%) with a *worse* p-value
   (0.375) — the signature of noise, not signal.
3. The effect is 0.32 µg/m³ on a base of ~14 µg/m³, at n=10 targets.

`test_no_spatial_result_survives_multiplicity_correction` fails loudly if any spatial
comparison ever does survive correction, so this cannot quietly become a claim.

**Now prevented by:** `aq.data._interpolate_short_gaps`. Tests:
`test_short_interior_gaps_are_fully_filled`,
`test_over_long_interior_gaps_are_left_entirely_nan`, `test_mixed_gaps_in_one_series`,
`test_gaps_touching_an_endpoint_are_never_filled`, `test_nan_runs_identifies_interior_correctly`,
and `test_new_loader_differs_from_the_originals_only_on_over_long_gaps`, which pins the
change to exactly 306 values.

> **A note on what equivalence testing does and does not buy you.** The six original
> loaders were byte-identical modulo whitespace, and a test asserting the new loader
> matched them passed — while all seven were wrong. Cross-implementation agreement and
> correctness are different properties, and only the second one needs a semantic test.

### 8.3 Reproducibility statement (for the paper)

> The analysis pipeline was re-executed on a different platform and software stack from
> the one on which the results were originally produced (Linux / Python 3.12 → macOS /
> Python 3.11; numpy 1.x → 2.4; pandas 2.x → 3.0; torch 2.x → 2.13). Five deterministic
> result tables — `verify_neighbor_ablation`, `stage5b_common_ablation`, `stage4_extreme`,

> of 3.8 × 10⁻¹³ (maximum relative deviation 3.1 × 10⁻¹⁴), consistent with BLAS-level

> reproduced exactly. The stochastic LSTM stage reproduced to a maximum relative deviation

> 10 of 12 targets, p = 0.0068 and p = 0.0034 at K = 30 and K = 90 respectively).

> and gate the stochastic comparison on the decision (win-rate ≥ 9/12 and p < 0.05) rather
> than on individual decimals. Bitwise equality is not a valid cross-platform criterion for
> this pipeline.

### 8.4 Caveats to state

n = 12 target stations, underpowered below roughly a 1% effect. Slice-dependent n from the
≥5-day reporting rule (§6.3). Single city, single pollutant, next-day horizon only. No
meteorological covariates — wind speed and direction are the obvious omission for dust
events, and their absence is a plausible partial explanation for the extreme-day failure.
